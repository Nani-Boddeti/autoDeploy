## Design Context

### Users
- One operator (the owner) running a self-hosted control plane. Mostly works on a laptop and sometimes a phone.
- Jobs: see whether every environment is healthy, check what is live, deploy or retry a commit, read why a deploy failed, roll back, resolve blocked activations, and manage servers, config and routes.

### Brand Personality
- Calm, precise, quiet. Like a well-made instrument panel.
- Emotional goal: confidence. Failures read clearly and without alarm, and the next action is obvious.

### Aesthetic Direction
- Soft pastel OKLCH surfaces with neutrals tinted toward one brand hue (lavender-blue, about 260 to 290).
- Color is reserved for state: ok, busy, failed, and needs attention.
- Theme: light by default, with automatic dark mode via prefers-color-scheme.
- Dense but airy tables, with tabular numerals for times, IDs and digests.
- Anti-references: generic SaaS admin templates, hero-metric dashboards, identical card grids, glassmorphism, side-stripe callouts, gradient text, neon on dark.
- Hard constraints:
  - CSP is same-origin only: no inline style, no inline script, no external fonts or CDNs.
  - Fonts are self-hosted and embedded.
  - JS is limited to one same-origin file for live logs, with a no-JS fallback.

### Design Principles
1. Every page is reachable from the nav. No page needs a typed ID, and no page renders text alone.
2. State first: status, failure class and failure reason sit next to the thing they describe.
3. Actions sit inline where the decision is made (deploy, retry, roll back, resolve, cancel). Danger actions require an explicit confirm.
4. Keep information parity: the redesign removes no fact the current UI shows.
5. Use restraint: one accent, a varied rhythm of spacing, and no decoration that conveys nothing.
