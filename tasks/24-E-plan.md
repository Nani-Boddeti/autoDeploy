# 24-E GitHub App manifest flow — detailed plan

Date: 2026-11-27. Status: DONE 2026-11-27, pushed (owner approved; no changes outside the GitHub setup scope). Parent: tasks/24-plan.md (24-E). Amends ADR 0002.

## Owner decision (2026-11-27)
- **E-D1 storage = DB + self-restart** (replaces the spool + root `.path` design in 24-plan.md). Reason: the control plane unit writes nothing to disk (`ProtectSystem=strict`, no `ReadWritePaths`); a root oneshot parsing CP-written files would be a new privilege boundary. Chosen: CP stores the App PEM + webhook secret KEK-encrypted in Postgres, exits with a dedicated code, systemd (`Restart=on-failure`) restarts it, startup loads the App from the DB.
- Rejected: spool dir + root `github-apply` unit (privilege boundary, new writable path); hot-wiring the App without a restart (main.go wires webhook handler, setup service, checkout, lister only at startup; large refactor).

## Sources verified 2026-11-27 (docs.github.com)
- Manifest flow: https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest
- Conversion: https://docs.github.com/en/rest/apps/apps#create-a-github-app-from-a-manifest
- Form POST `https://github.com/settings/apps/new?state=S` (personal) or `https://github.com/organizations/ORG/settings/apps/new?state=S`; field `manifest` = JSON string.
- Redirect `redirect_url?code=C&state=S`; code valid 1 hour (single use not documented: treat as single use).
- `POST https://api.github.com/app-manifests/{code}/conversions`, no auth, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2026-03-10` (= existing `githubapp.APIVersion`). 201; 404; 422. Response: `id, slug, node_id, owner{id,type,login}, name, html_url, client_id, client_secret, webhook_secret (nullable), pem, permissions, events`.
- App name max 34 chars, unique on GitHub.
- Not documented, inferred: manifest permission keys `contents: read`, `metadata: read` (REST response uses those keys). VPS round confirms.

## Invariants
- Host env file wins: `AUTODEPLOY_GITHUB_APP_ENABLED=true` (enable-github.sh, break-glass) → DB App ignored, `/github` says so. DB App used only when the env config is not enabled.
- At most one DB App (singleton). Replacing/deleting an App = break-glass, out of scope.
- Code exchange only in a same-site POST with valid session + CSRF + unconsumed, unexpired state bound to that session. The cross-site GET callback never exchanges.
- State consumed atomically (in the same tx that checks no App exists) BEFORE the exchange: replay or a second tab cannot create a second GitHub App.
- PEM, client_secret, webhook_secret, code, state never logged, never rendered, never in audit rows. client_secret is not stored (unused: no user OAuth).
- Secrets at rest: crypto.Encrypt envelope with a new purpose `control_plane` + delivery `control_plane` (existing build/runtime/provider rules unchanged; distinct AAD domain, no collision with project secrets). Scope: OwnerID=owner, ProjectID="system", EnvironmentID="system", VariableID=`github-app-private-key` | `github-webhook-secret`, SecretVersionID=registration id. Wrap ledger reservation as for every Encrypt.
- No KEK active (no secret subsystem) → create refused with a clear message (install.sh always runs `enable-github.sh --kek-only`).
- `webhook_secret` null/empty, bad PEM, missing id/slug/client_id, unknown owner type → reject; show the App `html_url` + "delete this App on GitHub, then retry"; log app id only.

## Flow
1. `GET /github`, no App (env or DB): only a "Create GitHub App" form: account type (personal | organization), org login (GitHub login regex, required for org), App name (default `AutoDeploy <host>` truncated to 34, editable, ≤34, printable). Env App: unchanged page + note if a DB App also exists. DB App: unchanged page (install/bind/refresh).
2. `POST /github/create` (session + CSRF + provenance, strict field count): refuse if an App exists; create manifest state (digest stored, bound to owner/user/session/auth_revision, 10 min, cap per session like 000005); render an auto-submit page (one visible "Continue to GitHub" button, no inline JS — CSP is `script-src 'self'`) with a form POSTing `manifest` to GitHub with `?state=`.
   Manifest: `name`, `url`=origin, `hook_attributes{url: origin/webhooks/github, active: true}`, `redirect_url`=origin/github/create/callback, `setup_url`=origin/github/setup/callback, `setup_on_update: true`, `public: false`, `default_events: ["push"]`, `default_permissions: {contents: read, metadata: read}`, `request_oauth_on_install: false`. Mirrors what enable-github.sh tells the operator to configure.
3. `GET /github/create/callback?code&state` (exactly 2 params, length/charset checked): no session needed (cross-site drops the Strict cookie); set a SameSite=Strict handoff cookie holding code+state (same pattern as `/github/setup/callback`), render "continue" page.
4. `POST /github/create/complete` (session + CSRF + provenance + handoff cookie): in one tx: lock singleton, verify no App, consume state (owner/session match, unexpired). Then conversion call (10s timeout, no redirects, 1 MiB limit, strict decode). Then in one tx: encrypt PEM + webhook secret, insert registration (app id, slug, client id, owner id/type/login, html_url, envelopes), audit row (no secrets). Clear handoff cookie. Render "Applying… restarting" page with meta refresh to `/github` after ~10s.
5. After the response is flushed: log `github app created; restarting to load it app_id=N`, cancel the root context, process exits with code 75 → systemd restarts (RestartSec=3).
6. Startup: env not enabled + DB registration present → decrypt with the KEK ring (once, at startup), build `GitHubAppConfig` (installation URL `https://github.com/apps/<slug>/installations/new`), signer from PEM bytes, webhook ring (version 1, active secret) → same wiring path as the env App. Decrypt/parse failure → startup fails with "GitHub setup unavailable" (same as env path today) so it is visible, not silently half-configured.

## Edge cases
- Owner abandons on GitHub: state expires; App may exist on GitHub without being converted → re-run creates a new state; GitHub name collision → GitHub page lets the owner rename.
- Code older than 1 hour / already used → 404/422 → "start again" message; state already consumed so retry needs a new create.
- Conversion OK, DB insert fails → App orphaned on GitHub: show html_url + delete instruction; log app id.
- Restart loop: decrypt failure at startup → fails like today's env path; systemd start limit stops the loop; journal names the cause; break-glass env file overrides.
- lan mode: creation works; GitHub cannot reach a private webhook URL (existing limitation, documented).
- Two tabs: second `complete` sees the consumed state / existing App → refused, no second conversion.

## Risks
- Self-exit restart: in-flight requests dropped (admin-initiated, seconds). StartLimit: one exit per create, well under default burst.
- Two config sources: mitigated by strict precedence + visible note on `/github`.
- Manifest permission key names inferred: proven only in the VPS round (checklist step 10).
